Privacy Policy

Last updated: November 14, 2026

Hibernate Tabs, Windows, and Sessions performs hibernation decisions inside the browser. It does not operate a developer server, include analytics or advertising, sell data, or transmit browsing data to the developer.

Chrome Web Store Limited Use

The use of information received from Google APIs adheres to the Chrome Web Store User Data Policy, including the Limited Use requirements. HTWS uses browsing data only to provide its user-facing tab hibernation, protection, activity-history, bookmark, and restore features. The developer does not receive this data, allow humans to read it, use it for advertising or credit decisions, or sell or transfer it to third parties.

Data Used

The extension reads tab URLs, titles, window membership, last-active time, pin and group state, audio state, and limited browser-visible safety state. With optional website access it records only yes-or-no signals for playing media, Picture-in-Picture, active streams, and modified forms. It never reads form values or page text.

Hibernation stores restoration metadata locally. Local extension storage also keeps a bounded activity log containing operation time, outcome, tab title, and URL. General protection preferences may be synced by Chromium when browser profile sync is enabled; archive metadata and activity history remain local.

Automatic hibernation keeps per-tab last-active timestamps in temporary extension session storage. These timestamps are used only to identify tabs that have reached the selected inactivity delay and are cleared when the browser session ends.

Imports, Exports, And Bookmarks

Archive, activity, and Never-Hibernate site-rule exports are generated locally as JSON files only when the user selects Export. Imports read a user-selected JSON file locally, validate it, and merge accepted records into extension storage. Neither operation sends the file to the developer.

Browser bookmarks are created only when the user explicitly selects a bookmark action. Those bookmarks remain ordinary browser bookmarks if the extension is later removed.

Permissions

  • Alarms: wakes the extension periodically to check for inactive tabs that have reached the selected automatic hibernation delay.
  • Bookmarks: creates, reads, renames, and removes real-URL bookmark copies only when the user selects a bookmark action.
  • Context menus: adds commands for hibernating a tab, window, or session and for adding the current site to Never Hibernate.
  • Tabs: reads tab state and closes explicitly or automatically hibernated tabs, then recreates restored tabs.
  • Tab groups: records and reconstructs browser tab groups during restore.
  • Storage: stores preferences, site rules, archive metadata, page-safety signals, undo and redo history, and Activity History.
  • Scripting and optional website access: observes only boolean media, capture, Picture-in-Picture, and modified-form safety signals when the user enables that protection.

Ignore Protection applies only to the user-initiated window or session action where it is selected. It does not make prohibited URL types eligible and does not expand the data the extension reads or stores.

Private And Incognito Tabs

Incognito access is optional and must be enabled in the browser's extension settings. Private tabs stay open by default. If the user chooses local private archiving or Activity-only logging, the associated titles and URLs are stored in extension storage that Chromium shares with the regular profile. Private archive records restore into private windows and cannot be copied into browser bookmarks by HTWS.

User Control

Users can clear activity history, permanently erase individual archive entries or the entire local archive, remove saved browser bookmarks, revoke optional website access, export their data, or remove the extension. Removing the extension deletes its local storage; explicitly created browser bookmarks remain until the user removes them.
